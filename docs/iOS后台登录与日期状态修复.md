# iOS 后台登录与日期状态修复

## 反馈与原因

用户反馈后台登录不可用、输入密码后偶发超时，以及切换日期时已提交日志仍显示红点。

- 登录流程原先先等待账号输入框，再检测业务会话。Cookie 恢复成功且登录框消失时，反而一直等待；加载页面也会耗尽认证剩余时间。
- 隐藏 WKWebView 的焦点事件不能保证与可见页面相同，重复失焦会重新解析用户并清空密码。网页密码错误、账号锁定或需要额外确认的结果也没有及时传给 App。
- 周条数字来自考勤，状态点来自 BOSS 缓存，两者不能互相推导。旧缓存仅凭整月时间戳便能判定缺席日期为零；部分请求失败和不合法响应还可能被转换为空结果，进而误标待补交。
- 手动月度同步未保护查询期间的提交或切月，旧回包可能覆盖新的日期数据。

## 修复规则

- 先检查同一账号的有效业务会话，再填写登录表单；登录成功必须有 LoginID、真实认证回调及匹配的业务请求，UserID 本身不能证明认证完成。
- 使用网页原有 blur 处理一次和原有密码加密/认证函数，密码只提交一次；账号框支持同源 frame。错误仅返回固定原因码，不输出密码或会话报文。
- 分开限制页面加载和认证等待时间，并展示密码错误、账号锁定、额外网页确认、账号不符等明确提示。
- 严格解析单日工时三元组，支持 JSON 字符串包装；无效数字或任一天失败均不能写成成功的整月零工时。
- 保留已有金额，但旧版缓存不再自动获得有效状态。逐日保存确认证明，超过 15 分钟、时间异常或未确认时显示待确认；近期确认正工时才是已提交，近期确认零工时且过去有考勤才显示待补交。
- 提交后只使对应日期确认失效，其他日期证明保留；日/月写入继续串行合并，按查询开始时的版本拒绝过期回包。周数据读取期间版本变化时，不混用旧金额与新证明。
- 后台自动、网页手动和月历手动三个整月写入入口均使用严格解析；月历固定目标月份、回读合并缓存，并仅在当前月份匹配时更新界面。

## 验证与边界

- 已将当前 BOSS 原始 LoginCheck、GetUserPassword 和 Security.Login 与生成脚本联合执行，验证单次 blur、单次 TryLogin、密码清理与认证回调阶段。网络/DOM 使用测试替身，不能代替真机账号登录验收。
- 回归覆盖旧缓存迁移、证明有效期、单日零/正工时、部分失败、多层字符串响应、并发写入及日期切换。
- 本次 iOS 试用版为 2.11.2(14)，生产入口 lib/main.dart；Android 发布版本不变。安装与真实业务交互状态另见操作记录。

- 最终结果：655项测试全部通过，静态分析无问题，Release构建和IPA签名校验通过；真机安装尚未完成。
