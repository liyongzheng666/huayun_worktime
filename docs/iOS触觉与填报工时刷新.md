# iOS 点选触觉与填报工时刷新

## 反馈与定位

用户反馈iOS部分点选没有震动，希望打开软件或提交日志后自动刷新日志界面对应日期的填报工时。

- 新工作台、主题选择及iOS导航使用普通按钮/InkWell，漏接原有HapticUtils；基础模式又把iOS选择反馈直接跳过。
- 原日志页刷新主要更新周条，主工时卡展示的是打卡工时；15分钟月缓存也会跳过刚提交后的查询。
- 单日写入可能被当作整月同步，同月并发写入或旧月份回包还可能覆盖新数据。

## 修复

- 补齐工作台刷新、核对工时、主操作、日期、主题、导航及外观入口触觉；不等待触觉完成才处理业务，不对禁用/已选项重复触发。关闭设置仍有效，Android基础模式保留原语义。
- 日志页启动、切换日期、回前台时查询选中单日；今日工作台默认查询同样使用共享单日刷新流程。
- 提交成功/确认已存在/编辑成功后，复用当前网页会话查询该日总填报工时。读取失败不推翻已确认的保存结果，不写入猜测的工时。
- 本地工时缓存变化后通知页面，仅复读本地，不造成网络请求循环；周条拒绝已失效的旧加载结果。
- 工作时长卡分开显示“BOSS已填报”和“打卡工时”。刷新失败显示上次记录；已知已填报且没有本地编辑ID时，主入口改为打开BOSS查看。
- 工时写入串行并以版本保护并发回包；保存确认后先标记对应日期已变化。强制单日刷新等待旧请求后重新查询。单日0可明确确认，但不会伪造全月同步。
- 旧月回包遇到期间发生变化且尚无新值的日期时，保持该日未知并移除整月确认时间戳；失效旧单日请求也不会把缺席缓存补成0。
