# 月度日详情签到照片

更新日期：2026-11-16。

## 原因与入口

旧每日页在 `_buildTypeWarning` 内显示“查看打卡照片”；新版今日工作台未接入这个入口。iOS 工作台提交 `f56d6a3` 首次引入该布局，双端统一提交 `7d955a7` 将同一布局扩到 Android。照片解析与大图页仍存在，不能据入口缺失判断后端已删除照片。

现按用户要求，把上班、下班照片分别放到“月度 → 点击具体日期 → 窗口底部”的并排文字按钮中，使用 `AttendancePhotoDialog` 照片弹层提供缩放与保存能力。只有上班卡、工时为零时也保留入口；此功能不依赖日详情的正工时展示条件。

## 按需查询与复用规则

- 打开月度页、打开日期窗口、调整日期类型均不额外请求照片地址，也不预加载图片。
- 现有考勤同步响应已经携带照片地址时，聚合、月度合并、单日刷新和快速同步一并保留，不为照片增加请求。
- 只有点击“查看上班照片”或“查看下班照片”且地址尚未查询过时，才补查该日；该接口同时返回两个地址，另一个按钮复用结果。
- 同团队、员工、日期的在途查询合并，快速点击、关闭重开不会重复发起日查询。
- 成功取得的地址和“明确无照片”均写回内存及月度持久缓存；切月、重启后复用。成功图片字节在本次运行中保留最近六张，配合 Flutter 解码图片缓存复用，并非永久离线存储。
- 缺少字段表示旧缓存尚未查询，字段为 null 表示已确认无照片；失败显示重试提示，不缓存成“无照片”。只有用户再点具体照片才重试。
- 缓存失效后的正常考勤同步更新照片信息，不为照片建立轮询或新的整月重查；照片单独变化不改变快速同步的历史停止边界。
- 补查只合并照片字段，不能用打开窗口时的旧快照覆盖期间修改的工时或手动标记。窗口关闭后的迟到响应不打开预览或更新已销毁的窗口。

### 2026-11-16 第二张照片挂起：连接复用修复与照片弹层

用户进一步明确：先上班后下班时第二张打不开，反向亦然。这与照片类别无关。真实地址经脱敏探针验证：共享Dart HttpClient（与旧NetworkImage一致设置autoUncompress=false），上→下首张4209ms成功、第二张12006ms超时；下→上首张4138ms成功、第二张12003ms超时。每张独立Client时，上→下4870/4031ms均成功，下→上5274/4200ms均成功。两天四张JPEG均约40–46KB、系统解码成功。结论是该图片接口与共享持久连接的兼容问题；没有把业务地址缓存或图片解析误判为本次主因。原始签名URL及账号参数未写入报告。

- 下载改走 `AttendancePhotoLoader`：每张独立Client、finally关闭；请求和解码有12秒上限；失败有明确提示、显式重试，不自动循环。
- 成功图片字节保留最近六张，同URL在途合并；保存通过 `Gal.putImageBytes` 使用同一份字节，不再下载或写临时文件。
- 月度底部入口保持并排小按钮，查看只弹出照片Dialog，关闭即回原详情，保留缩放和保存，不另开整页。旧每日入口也去掉同时预加载两张缩略图，统一点击才取图。
- 只有图片响应401/403/404/410或无效内容，且用户明确点击重新加载时，才强制刷新该日地址；超时重试仅重取图片，不重查整月。正常打开继续复用地址。
- 顺序回归实际解码图片，并计数：连续上→下→上→下和反向顺序均只下载两次，打开详情零图片请求，保存零额外下载。另覆盖同URL并发合并、错误不缓存、超时结束等待和明确刷新地址后继续复用。

接口实测与回归不能替代手机体验；本次试用构建号24，安装/启动结果见操作记录。
