# 工时十进制精度修复

## 问题与最小复现

用户报告远端填报10.20，客户端显示10.19。真实解析、StorageService保存与回读均保持数值10.2，旧formatHours将二进制浮点数乘100再truncate，得到10.19。手输解析也使用相同算法，编辑框仅改标题时可能把错误默认值写入更新对象。

- 远端10.20 → 旧显示10.19；修复后10.20。
- 远端1.15 → 旧编辑默认1.14，仅改标题可能继续降到1.12；修复后默认、更新对象均为1.15。
- 4.10、0.29等也受影响。

最小回归命令：`flutter test --no-pub test/utils/reported_hours_precision_test.dart`。修复前3项失败，包含解析→真实缓存→显示链路。由于断言已直接隔离格式化/手输截断，解析和缓存断言通过，本问题不再展开不相关的根因猜测。

## 修复口径

- 共享DecimalHours按十进制文本取百分之一小时整数，超出两位朝零截断，不使用epsilon或四舍五入掩盖误差。
- 显示、手输、月度分配的边界解析与整数格式化共用此工具。原有整数紧凑显示约定保留，浮点显示固定两位。
- 分钟换算直接使用整数`minutes*100~/60`，避免先除再乘少掉百分之一小时。
- 月度累计、工作台累计、整月API汇总及目标差额按整数边界加减，防止10.20重复累计后显示30.59。
- 输入拒绝非有限数值、非法范围和截断后为零的工时，继续保留正数至24小时的单次填报范围；已填日合计超过24小时仍允许读取供纠偏。
- 不猜测重写远端历史记录。若旧缓存本身已是错误值，应以远端真实记录和重新同步结果核对，不能仅靠数值反推原值。

## 验证

- 全套839项通过，静态分析无问题；本轮新增21项回归。
- 覆盖0.01—24.00的全部2400个两位小数往返、全天1441个分钟值、科学计数/符号/前导零/非法值、重复转换及月度累计。
- 真实编辑组件回归覆盖10.20/1.15/4.10默认输入和只改标题后的更新对象；真实月度界面验证3个10.20显示30.60。
- 测试使用响应替身与本地缓存，未使用真实账号向华天保存日报。

## 性能排查边界

另有用户确认页交互卡顿和华天时长计算慢的问题。桌面数据层读取中位约1毫秒、纯分配约3微秒，不能当作手机帧率。Instruments附加未成功，未生成有效真机trace；后续采用Profile AOT试用包及Flutter自身Timeline继续采集。精度修复通过不能代替卡顿修复验收。
