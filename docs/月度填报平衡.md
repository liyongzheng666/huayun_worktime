# 月度填报平衡与月底提示

## 已确认的需求

- 以当月已完成日期的实际工时合计减去实际已填工时，得到未填日期可分配额度。已填日期的多报和少报都参与余额计算；已填记录和原始考勤只读。
- 对未填且有实际工时的日期，推荐 0.10 小时粒度的填报值。在合计约束下尽量贴近每天实际工时。显示保留两位小数，例如 10.40。
- 示例：10.42、10.37、10.41 三天均未填，推荐 10.40、10.40、10.40，合计均为 31.20。
- 例如可分配额度为 31.26 时，建议合计为 31.20，0.06 作为尾差保留展示；月底最后一个实际工作日起，打开 App 提示能凑整则利用，最终不足 0.10 的部分可舍弃。
- 最后工作日使用现有节假日计划、考勤日期类型及手工标记，包含调休工作日。
- 没有未填日期却有差额、已填总量超过实际总量或无法在日上限内分配时，展示差额并提醒手动编辑已填日志。
- 先查看整月预览，再明确采用所选日期建议，最后仍走现有单日提交确认、提交前查重和未知状态暂缓流程。不会批量或静默提交。
- 提醒在 App 内展示，不发送系统通知。Android 和 iOS 共用该功能，保留各平台原有首页与提醒实现。

## 实现边界

- 纯算法只处理 0.01 小时的整数，按 0.10 小时步进，建议值范围 0.00—24.00；金额格式化也不依赖浮点乘除。
- 数据适配只读现有缓存，合并既有手工工时口径；过期、缺失、未完成的当天、污染数据和读取期间变化均不能冒充可用月度总额。
- 请求建议时复用现有华天刷新器获取过期月份数据，不新增另一套会话或提交服务；启动提示仅读取缓存。
- 月度计划在采用和最终确认时重新核对数据指纹。采用后手工修改或切换工时来源即按用户输入处理；月度数据变化则要求重新生成建议。
- 推荐为零时保留预览并提示人工核对，不允许通过建议按钮提交零工时。
- 月底提示卡片与原首页同时显示，避免启动弹窗干扰账号准备和新手引导。启动、回前台、已有工时更新和主页面刷新后复查；不扫描全部历史月份。

## 验证计划

- 算法：用户样例、多报/少报抵扣、尾差、无待填、超额、日容量、稳定顺序及整数不变量。
- 数据：真实 StorageService 缓存、手工标记、调休、未知/过期/并发状态、未来日期和当天未下班。
- 交互：预览与采用分离、所选日期建议准确进入原确认框、手改与来源切换、数据变化阻止采用/确认、月底启动提示及生命周期。
- 完成后运行相关回归、全套测试与静态分析。构建、签名、安装、启动、真实账号交互分别记录，不能用测试或安装替代用户验收。
