# iOS 今日收尾试用

## 范围

用户希望先在 iOS 提升每日使用便利性。本轮只做“每日工时”顶部的今日收尾卡片及对应操作入口，Android 不展示卡片、不增加今日服务请求；Android 正式版本保持 2.9.1+10。

iOS 试用构建使用 `--build-name=2.10.0 --build-number=11`，不改共享 pubspec 的 Android 发布版本，不创建 Android Release tag。用户已指定安装到 xl666（UDID `00008140-000231542862201C`）。

## 行为

- 三项汇总：打卡记录、当天 CSV 素材、BOSS 单日提交状态。
- 先读取本地素材及历史缓存，再以只读单日查询核对提交状态，不增加整月查询。
- 明确区分未知、需要登录、确认未提交和确认已提交；旧缓存标明“上次记录”，不冒充实时结果。成功查询显示时间，15 分钟后自动转待确认；跨午夜隐藏昨日卡片，不擅自改变用户选择的日期。
- 主操作可进入导入 CSV、登录 BOSS、原有提交确认、查看已提交日志或核对日期/工时。休息、请假、出差用中性说明，不把卡片当考勤合规判断。
- 原有提交前防重检查和用户确认完整保留。跳转日志页时固定目标日期，加载期间禁用提交/编辑并丢弃旧日期数据。
- 每日数据与卡片异步请求都检查加载序号，防止过期返回覆盖当前日期。存储异常显示重试，不误报素材缺失。

## 实现与验证

- `TodayWrapUpSummary` 负责展示规则；`TodayWrapUpService` 只读素材和单日 BOSS 状态；`TodayWrapUpCard` 只展示并回传操作。
- `PlatformCapabilities.supportsTodayWrapUp` 控制 iOS 先行。
- 测试覆盖未知/零/正工时、日期和15分钟时效、缺卡、休息出差、跨天、并发查询、大字体和窄屏、Android零请求、真实页面CTA、午夜和错误恢复。
- 模拟器使用临时入口与测试数据核对排版，临时入口不进入真机正式构建。视觉检查不等同用户交互验收。
- 真机安装前核对签名与 profile 包含指定 UDID；优先覆盖保留原数据。若系统拒绝跨团队覆盖，不卸载原 App，改用独立试用 Bundle ID 并说明。

## 体验重点

打开首页能否快速理解下一步；导入/登录/提交入口是否直达；返回首页是否更新状态；弱网时是否清楚标为待确认；最后由用户在 xl666 上验收。
