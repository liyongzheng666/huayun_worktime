> **维护对象**：任何 AI 助手和人类读者。
> **目的**：记录每一次对代码或文档有实际变更的事项，防止上下文在长会话或跨会话中丢失。

## 维护规范

1. **每个条目必须有状态**：🟢 已完成 / 🟡 进行中 / 🔴 废弃
2. **废弃条目处理**：确认无历史参考价值后删除；有保留价值的（如设计方向曾被尝试后放弃）改为废弃态并注明原因
3. **新条目追加**：按时间顺序，新增在同 Phase 节末尾或创建新节
4. **内容底线**：做什么 + 为什么 + 结果。不记录纯讨论/调研，只记录对代码或文档产生了实际变更的事项
5. **时效性**：进行中的条目超过 7 天无更新，主动询问是否仍有效或标记废弃

### 🟢 iOS 平台迁移：提醒链路平台化改造

- **做什么**：项目由 Android-only 扩展为 Android + iOS 双平台。新增 `PlatformCapabilities` 平台能力探测，把 `ReminderScheduler` 接口从 `reminder_coordinator.dart` 拆出独立文件，新增 `AndroidReminderScheduler`（原 AlarmManager 逻辑原样迁移）和 `IosReminderScheduler`（`zonedSchedule` + `DateTimeComponents.time` 每日重复本地通知）。
- **为什么**：iOS 没有「在指定时刻唤起进程执行代码」的能力，本地通知的标题和正文在调度那一刻就被系统冻结，触发时 App 进程不会启动。因此 Android 侧「到点联网拉考勤再拼实时文案」的链路在 iOS 上无法复制，只能降级为固定文案。按项目「相似相溶」要求，平台判断集中到 `PlatformCapabilities`，不散落各文件；按「拓展预留」要求，能力以 `supportsExactBackgroundAlarm` 这类语义命名暴露，而非直接暴露平台名。
- **结果**：`ReminderCoordinator` 行为和接口完全不变，仅默认实现改为按平台选择，因此其原有 4 个测试一行未改即通过。修复 3 处 iOS 上的真实缺陷：`NotificationService.initialize()` 无条件调用 `AndroidAlarmManager.initialize()`（iOS 必经此路径）、「测试生效」中的 `exit(0)`（Apple HIG 禁止 App 主动退出，iOS 改为预约本地通知并提示回桌面）、缺失 `NSPhotoLibraryAddUsageDescription`（保存打卡照片时会直接崩溃而非弹权限框）。设置页三处 Android 专属文案（自启动、省电优化）与「权限设置」入口按平台分支。`checkAllPermissions()` 在 iOS 上不再把系统不支持误报为用户拒绝。

  2. 边界取「**超过** 140%」而非「达到」——刚好卡线就开始闪会造成打扰。
  3. 闪烁用透明度在 100%↔35% 之间往复（750ms），**不做整块显隐**：整块隐藏会让该行高度来回跳动，观感像故障而非提醒。

- **行为变更说明**：新规则以固定的 100% / 140% 为界，**不再与基础目标挂钩**。此为用户明确指定，已告知如需绿色从基础目标起算可改两个常量。
