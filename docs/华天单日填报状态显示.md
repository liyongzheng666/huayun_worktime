# 华天单日填报状态显示

## 问题

用户反馈未填写华天日报的日期被显示为填报时长0.0。日志页把确认零合计直接格式化为“BOSS已填报0.00小时”，月度详情把确认月份中的缺席日期补零并套用“已填”文案，导致未填与真实填报记录混淆。

## 统一规则

| 当前证据 | 单日显示 |
| --- | --- |
| 当日查询已确认未填合计，且无已知日报记录线索 | 未填报，不显示已填0小时 |
| 已确认正数工时 | 已填及实际工时，保持两位十进制精度 |
| 尚未同步、过期、失败或无效响应 | 待确认；旧正数可另标上次已填，不能冒充当前状态 |
| 零合计但有历史日报对象ID线索 | 已有日报记录，工时待核对，不断言当前仍有记录或已删除 |

共享BossReportStatus只组织展示状态，不修改远端或工时金额。日志页读取月快照、确认时间与记录线索；月度页同一规则，已打开详情也随状态/记录线索变化更新。周条的主要数字属于打卡工时，今日收尾已有“尚未提交/待确认”的文字区分，不能把这些正常打卡数值误改。

## 接口边界

GetWorkHours返回已填合计，没有recordExists字段；完整月响应的零合计与缺席行均表示现有业务口径下的未填状态。历史对象ID可能过期，只作为冲突核对线索。此次修复不宣称新增实时零小时记录识别，也不增加逐日记录明细网络请求；保持月度合计、建议预算与提交前查重算法不变。

## 验证

先在真实日志页和月度详情复现未填显示“已填0”的红测试，再验证确认未填、完整空月、未知/过期零、旧正数、历史ID冲突、金额精度与已打开详情更新。构建和设备安装结果在操作记录中分别记录。
